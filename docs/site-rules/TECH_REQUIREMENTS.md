# 生成サイトの品質ルール（全工程横断）

このドキュメントは、パイプラインの各工程で生成サイトに適用される**全ルールを工程別に整理**したものです。ルールの正本は各プロンプトファイル（`.txt`）であり、本書はその人間向け索引です。

## ルール資産の所在

| 正本ファイル | 適用タイミング | 内容 |
|-------------|---------------|------|
| `config/prompts/common/technical_spec_prompt_block.txt` | TEXT_LLM 最終実装段（step 7-1 / 8-1） | 全プラン共通の品質ガードレール（84行） |
| `config/prompts/common/claude_tech_requirements.txt` | 各ステップに個別注入 | 技術スタック・@import・日本語折り返しの最小セット |
| `config/prompts/*_manual/step_*.txt` | TEXT_LLM 各ステップ | 工程固有のルール（情報設計〜実装） |
| `config/prompts/manus/orchestration_prompt.txt` | Manus リファクタ | ソース取得・ページ数厳守・コンテンツ量維持・画像生成 |
| `config/prompts/manus/refactoring_instruction_handwork.txt` | Manus リファクタ | App Router 分割・配色維持・Hydration 防止・446行 |

## 1. 技術スタック（全工程共通）

- **Next.js (App Router)**, React, **Tailwind CSS**
- セクション単位でコンポーネント化（1 セクション = 1 コンポーネント）
- CSS `@import`（Google Fonts 等）は globals.css の**最上部**（`:root` / `@theme` より前）。違反はビルドエラー

---

## 2. 情報設計（step 2〜3）

### ページ構成

| プラン | ページ数 | 特記 |
|--------|---------|------|
| BASIC LP | 1（LP） | ヘッダー/フッター禁止。法務はモーダル等で表示 |
| BASIC CP | 1 | サービス 4 つ以上ならタブ表示。沿革セクション禁止 |
| STANDARD | 6 固定 | TOP は下層への目次。会社概要・お問い合わせは独立ページ |
| ADVANCE | 12 固定 | ページ数が多い前提でドロップダウンナビ |

### 共通の構成ルール

- **プライバシーポリシーに独立 `page.tsx` を作らない** — 契約ページ数に含めず、既存ページ上で Dialog/Sheet/Drawer 等で表示
- **対応エリアの画像・イラスト禁止** — 所在地は Google Maps 埋め込み
- 同一ページ内遷移ボタン不可（STANDARD/ADVANCE）
- 下層ページは LP 相当の情報ブロック（料金・実績・FAQ 等）を欠かさない
- LP: 中間オファー 2 箇所以上、FAQ・お問い合わせ・会社概要は各 1 独立セクション
- LP: 実店舗なら Where 必須（会社概要と統合不可）、個人運営なら Who 必須

## 3. コンテンツライティング（step 3〜4）

### 文量の下限

| 対象 | 最低文字数 | 正本 |
|------|-----------|------|
| TOP ページ（STANDARD/ADVANCE） | 2,000 字以上 | `step_3_1.txt` |
| サービス下層ページ | 1,500 字以上 | `step_3_2.txt` |
| 会社概要ページ | 1,000 字以上 | `step_3_3.txt` |
| お問い合わせページ | 800 字以上 | `step_3_4.txt` |
| その他ページ | 800 字以上/ページ | `step_3_5.txt` |
| BASIC CP（1P 全体） | 2,500 字以上 | `step_3.txt` |

### セクション薄化禁止

- 見出し＋キャッチ 1 行だけで終えない
- 主要ブロックにはリード 1 文（誰の・何が解決するか）＋根拠・条件・手順・比較・事例型の具体を必ず載せる
- 箇条書きの項目を単語 1 つで終えない
- 「詳細はお問い合わせ」だけで中身を空にしない

### コンテンツの信頼性

- ヒアリング・仕様に**ない具体数値や実在固有名の創作は禁止**
- 不足時は「要ヒアリング」「プレースホルダ」として後工程で差し替え可能な文言に留める
- 法的・医療等の高リスク表現: 断定的効果表現や誇大広告を避ける

### ヒーロー（LP）

- キャッチ **15 字以内**
- サブはスマホ 2 行＋屋号必須
- 強み 3 つ（バッジ想定）
- ビジュアル必須

### FAQ

- 各回答は結論＋補足で**原則 2 文以上**（Yes/No 一言完結禁止）
- 業種で想定される不安・障壁・手続きをできる限り覆う
- STANDARD/ADVANCE サービス下層は最低 5 問

### フォーム

- プルダウン（対象）・名前・メール必須、電話、内容
- フォーム上に「2 日以内に連絡」文言必須
- 各入力に視覚的に紐づく `label`（`htmlFor` / `id`）
- `placeholder` は補助のみ

### ダミー禁止

- Lorem ipsum・無意味な英文の羅列・「サンプルテキスト」のみのブロック禁止
- 未確定は短い日本語プレースホルダ（例:「（料金は要確認）」）に留める

## 4. デザイン指示書（step 5〜7 / step 4〜6）

### 配色

| 項目 | LP | CP |
|------|-----|-----|
| 配色比率 | メイン 35% / ベース 60% / アクセント 5% | メイン 25% / ベース 70% / アクセント 5% |
| CV ボタン | アクセント色 | アクセント色 |
| 遷移ボタン（CV 以外） | — | メインカラー |
| 背景 | 白・低彩度系（stone/zinc/neutral 50〜100）が既定 | 同左 |

- `design_spec` の `color_scheme` / `tokens` を最優先。仕様にない派手な色の追加・全面ベタ塗り禁止
- Tailwind 任意値 `bg-[#..]` は design_spec 定義色のみ。即興で飽和色を増やさない
- 黒文字は `#333` より濃く（`#000` 禁止）、白文字は `#FFFFFF`
- アクセントはメインの補色寄り

### タイポグラフィ

- 見出し以外: **PC 16〜18px / SP 12〜14px** 例外なし
- CV ボタンは本文以上のサイズ
- H1 / ヒーローキャッチ: CP は目安 40px 以上（本文の約 2 倍）
- 見出し階層を飛ばさない（h1→h2→h3）
- 長文は `max-w-prose` 相当の可読幅を確保

### ヒーロー寸法

- 高さ: PC 750px / SP 550px 固定
- 必ず画像を用いる（画像なしの単色/CSS模様のみのヒーロー禁止）
- 画像上のテキストはオーバーレイで表示

### セクション間余白

- 非中間 CTA セクション: PC 100px / SP 50px
- 中間 CTA セクション: PC 50px / SP 25px
- 同一背景色の連続禁止
- CTA セクション背景は人物以外の画像＋オーバーレイ

### 装飾の禁止事項

- カード/ボックス内の絵文字・ロゴ禁止（LP は見出し〜リストへの絵文字も禁止、原稿にあるもの除く）
- 見出し下線装飾禁止
- グレースケール画像禁止
- 主要ブロックの大きな斜め配置禁止（装飾バッジ ±8° まで可）
- SP で画像過大配置禁止

## 5. 影・立体感・インタラクション（technical_spec + step 共通）

### 影

- カード・料金パネル等のコンテナ: `shadow-sm` / `shadow-md` または `ring-1 ring-black/5`
- `shadow-2xl` 以上の濃いドロップシャドウの乱発・ネオン風 glow・テキスト直接の影は禁止

### ホバー・アニメーション

- カード: `hover:-translate-y-0.5`〜`1` + `hover:shadow-md`（軽いリフト）
- ボタン: `active:scale-[0.98]`（押下フィードバック）
- `transition-colors` / `transition-transform` / `duration-200`〜`300`
- スクロール入場: `motion-safe:` 内で `opacity`・軽い `translate-y`・控えめな `scale`
- 複数カードの stagger: `delay-75` 段階（最大 ~300ms）

### 禁止されるアニメーション

- 自動再生・無限ループ・点滅・大バウンス・視認性を損なうパララックス過多
- `prefers-reduced-motion: reduce` で装飾的な動きを実質オフ

## 6. 実装段階（step 7-1〜7-5 / step 8-1〜8-3）

### コード構造

- STANDARD/ADVANCE: **単一ファイル・`useState` 擬似ルーティング**で全ページを内包
- LP: `app/**/page.tsx` 1 本のみ（法務はモーダル等）
- FAQ はアコーディオン必須
- CTA 行はボタン見た目
- カードの `mt-auto` で CTA 位置揃え

### 画像

- Unsplash・外部ストック URL 禁止
- ヒーローに必ず画像（`next/image` + `public/images/`）
- マニュアル段はプレースホルダ可。最終リファクタ（Manus）で置換
- `Image` の `src` は `/images/...`（`/public/` を含めない）
- `width` + `height` を数値で渡すか `fill` + 親に `relative`
- 非ヒーロー画像プレースホルダは SP 縦 300px 未満

### 下層ページヒーロー（STANDARD/ADVANCE）

- 全ビューに `ImagePlaceholder` 等
- 紺ベタ＋テキストのみの SubPageHeader 禁止
- `absolute inset-0` + 暗オーバーレイ + 前面見出し
- 共通 `SubHero` なら `props` で背景差し替え

### 日本語折り返し

```css
h1, h2, h3, h4, h5, h6 { text-wrap: balance; word-break: auto-phrase; }
p, li { text-wrap: pretty; word-break: auto-phrase; }
```

- `word-break: break-all` 禁止（日本語で不自然な切断）
- `white-space: nowrap` を h1〜h6・p・li に適用しない（SP オーバーフロー原因）
- 折り返し位置調整に素の `<br />` 挿入禁止（SP/PC 分けは `className` で制御）

### アイコン

- 基本: Lucide React（実在する名前のみ import）
- SNS: Simple Icons（`react-icons/si`）
- アイコンを画像プレースホルダで代用しない

### UX・アクセシビリティ

- タップ領域: 主要なリンク・ボタンは `min-h-[44px] min-w-[44px]` 目安
- フォーカス: `focus-visible:outline` でフォーカスリングを消さない
- ランドマーク: `<main>` を各ページに 1 つ、`nav` に `aria-label`
- モバイルで横スクロールを起こさない

### CTA・視覚的階層

- 1 ビューあたり primary CTA は 1 系統。副次は `outline` / `ghost`
- 虹色の複数 primary 禁止
- 同一文言のボタンを短いスクロール内に何度も並べない

### パフォーマンス

- ヒーロー等 LCP 画像に `priority` 付与
- 装飾・下層の画像は遅延読み込み、`sizes` を適切に指定

---

## 7. 絵文字の絶対禁止（全工程 Override 禁止）

- Unicode 絵文字を見出し・本文・リスト・表・ボタン・FAQ・フォーム・ナビに含めない
- `aria-label`・`alt`・`title`・コミットメッセージにも装飾用絵文字を入れない
- 例外: ヒアリング原稿に明示的に含まれる絵文字のみそのまま転記可
- 代替: タイポ階層・余白・配色・Lucide アイコンで強調

## 8. Manus リファクタ工程のルール

### コンテンツ量の完全維持（最重要）

リファクタリングは「コードの構造変換」であり「内容の編集・要約」ではない。

- 元ソースの全テキストを一字一句変更・省略・要約しない
- 表の行数・FAQ 数・カード枚数・リスト項目数を減らさない
- 料金・住所・メール等の具体的な数値・固有名詞をすべて残す
- 元コードのテキストを「そのままコピー」（自分の言葉で書き直さない）

### レイアウト構造の完全維持

- セクションのレイアウトパターン（全幅背景/2カラム/カード列/中央揃え）を変更しない
- 背景画像+オーバーレイ構造を CSS グラデーションに差し替えない
- 固定高さ（`h-[550px]` 等）を padding ベースに縮小しない
- コンポーネントの props をリネーム・削除しない
- グリッド列数・カラム比率を変更しない

### 配色の完全維持

- 元コードの `bg-[#...]` / `text-[#...]` のカラーコードを 1 つも変更しない
- テンプレートのデフォルト（白背景）で元コードの配色を上書きしない

### page.tsx のルール

- `app/**/page.tsx` 内に className・レイアウト要素を書かない（import + コンポーネント列のみ）
- 全 JSX は `app/components/` に移す

### 画像生成（nanobananaPro）

- 人物は必ず「日本人（Japanese）」を指定
- 画像に文字を含めない
- 保存先: `/public/images/`
- 背景画像は元コードと同じ CSS 手法で差し替え（サイド配置に変更禁止）
- 全プレースホルダを置換（残存禁止）
- 全生成画像がコードから参照されていること

### CSS・Hydration

- globals.css: 原則空。元コード `<style>` の移植 + 日本語折り返し CSS + アニメーション JS 接続のみ
- `<p>` 内に block 要素禁止
- `body` に `suppressHydrationWarning`
- `window` / `document` は `useEffect` 内
- Tailwind v4 時は `@theme` にトークン定義

### ビルド検証

- `npm run build` が通る状態がゴール
- エラー時は人間に聞かずログを読み、自己修復
- ページ数が契約と完全一致（自動チェック）

## ルールの改善方法

品質問題を発見した場合:

1. `output/<レコード番号>/llm_steps/` で**問題が発生したステップを特定**
2. `input.md`（プロンプト）と `output.md`（応答）を比較し、プロンプトの不足か LLM の傾向かを判断
3. **全プラン共通の問題** → `config/prompts/common/technical_spec_prompt_block.txt` にルール追加
4. **特定ステップの問題** → `config/prompts/*_manual/step_*.txt` を編集
5. **リファクタの問題** → `config/prompts/manus/orchestration_prompt.txt` または `refactoring_instruction_handwork.txt` を編集
6. **工程スナップショット**（`scripts/phase2_from_phase1_snapshot.py`）で同じ入力に対して改善効果を検証
7. 本書（`TECH_REQUIREMENTS.md`）を更新して索引を最新に保つ
