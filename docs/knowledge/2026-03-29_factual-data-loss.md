# ファクトデータ消失（Claude CLI step 7-4）

- **発生案件**: #16308（STANDARD CP）
- **発生日**: 2026-03-29
- **影響**: 生成サイトの会社名・住所・電話番号・代表者名がプレースホルダに置換

## 問題の詳細

STANDARD CP パイプラインのタブ⑥（コード生成 step 7-1〜7-5）において、step 7-4 の出力で顧客固有のファクトデータが汎用的なプレースホルダに置き換わった。

### トレース結果

| ステップ | 出力ファイル | ファクトデータ |
|---|---|---|
| 7-2 (015) | `output/16308/llm_steps/015_claude_cli_chat/output.md` | 正確 |
| 7-3 (016) | `output/16308/llm_steps/016_claude_cli_chat/output.md` | 正確 |
| **7-4 (017)** | `output/16308/llm_steps/017_claude_cli_chat/output.md` | **プレースホルダ化** |
| 7-5 (018) | `output/16308/llm_steps/018_claude_cli_chat/output.md` | 7-4 のエラーを継承 |
| Manus (019) | `output/16308/llm_steps/019_manus_refactor/` | 7-5 のエラーを継承 |

### 具体例（017 の出力）

- 住所: 東京都港区→「名古屋市中区」に変化
- 電話番号: 実番号→「052-XXX-XXXX」に変化
- 代表者名: 実名→「（代表者名）」に変化

## 根本原因

1. **単一ファイル再生成の注意劣化**: step 7-4 は TOP + 既存下層 + 新下層の全体を ~100KB の単一ファイルとして再生成する。この大量出力の過程で、入力コンテキスト（ファクトデータ含む）への LLM の注意が劣化
2. **コンテキスト不足ではない**: 累積トークン ~166K vs Claude Opus 4.6 上限 1M。問題はトークン量ではなく「長い出力生成中の注意分散」
3. **step 7-5 にファクトチェックがなかった**: 最終仕上げステップにファクトデータの照合指示がなく、7-4 のエラーがそのまま最終出力に伝播

## 実施した修正

### 層1: システムプロンプト注入（`--append-system-prompt`）

- **ファイル**: `modules/claude_manual_common.py`
- **内容**: `_run_claude_cli` に `--append-system-prompt` オプション追加。`ClaudeCLIChat` に `system_prompt` パラメータ追加（初回ターンでのみ CLI に渡す）
- **効果**: LLM はシステムプロンプトをユーザーメッセージより高い優先度で扱うため、ファクトデータへの注意が強化される
- **適用**: STANDARD CP / ADVANCE CP のタブ⑥（chat6）で `hearing_factual_data_block_for_prompt` をシステムプロンプトとして注入

### 層2: step_7_5 のファクトチェック

- **ファイル**: `config/prompts/standard_cp_manual/step_7_5.txt`
- **内容**: `{{HEARING_FACTUAL_BLOCK}}` プレースホルダを追加。「以下と照合し、相違があれば原本に合わせて修正」と明示的に指示
- **効果**: 最終ステップで事実データのクロスバリデーションが実施される

### 層3: Manus ファクトチェック

- **ファイル**: `modules/basic_lp_refactor_claude.py`
- **内容**: `hearing_factual_block` を Manus プロンプトに「ファクトチェック用データ」として注入
- **適用**: 全4プラン（BASIC LP / BASIC CP / STANDARD / ADVANCE）

## 効果の予測

| 指標 | 修正前 | 修正後予測 |
|---|---|---|
| 大規模サイト（6ページ超）でのデータ消失率 | ~50-70% | ~15-25% |

### 残存リスク

- step 7-4 の「全体を1ファイルとして再生成」する設計自体は変更されていない
- システムプロンプトも長い出力生成中の注意劣化を完全には防げない
- Manus の「元コードを100%維持」指示とファクトチェック指示が衝突する可能性

## 次のアクション

1. **効果測定**: 次の STANDARD CP / ADVANCE CP 案件で、step 7-4 出力のファクトデータを手動検証
2. **構造改善の検討**（残存リスクが高い場合）:
   - **差分出力方式**: step 7-4 で全体再出力ではなく、新規下層ページのみ出力させ Python 側で結合
   - **プログラム的検証**: LLM 出力から電話番号・住所・会社名を正規表現で抽出し、ヒアリングデータと機械突合
