# 下層ページのヒーローセクションに画像がない

- **発生案件**: #16308（STANDARD CP）
- **発生日**: 2026-03-29
- **影響**: 下層ページ（買取サービス、会社概要等）のヒーローが紺ベタ＋テキストのみ。画像なし

## 問題の詳細

生成されたサイトで、TOP ページのヒーローには `ImagePlaceholder`（→ Manus で実画像化）が配置されていたが、下層ページのヒーローは `SubPageHeader` コンポーネント（`bg-navy` のベタ塗り＋パンくず＋見出し）で実装されており、画像が一切なかった。

### 影響の連鎖

```
Claude CLI: 下層を SubPageHeader（紺ベタ）で生成
  ↓
Manus: ImagePlaceholder がある箇所だけ画像生成 → 下層はスキップ
  ↓
最終サイト: 下層ページのヒーローに画像なし
```

## 根本原因

### プロンプトの曖昧さ

step_7_3.txt / step_7_4.txt の指示:

> ヒーローに**画像（またはプレースホルダ）が必ずあること**

この「ヒーロー」が **サイト全体のメインヒーロー（TOP のみ）** なのか、**各ページのヒーロー** なのかが曖昧だった。Claude は前者と解釈し、TOP にだけ `ImagePlaceholder` を配置した。

### Manus 側は問題なし

Manus の `orchestration_prompt.txt` は「ソースに存在する `ImagePlaceholder` を実画像に差し替える」設計。元コードにプレースホルダがなければ画像を追加しないのは仕様どおり。

## 実施した修正

### プロンプトの明確化（STANDARD CP / ADVANCE CP 両方）

**step_7_3.txt / step_7_4.txt** の変更:

変更前:
> ヒーローに**画像（またはプレースホルダ）が必ずあること**

変更後:
> **各ページ（TOP・下層すべて）のヒーローに画像（`ImagePlaceholder` またはプレースホルダ枠）が必ずあること**（`useState` で切り替わるどのビューも単色ベタのみのヒーロー禁止。下層ページのヒーローにも `ImagePlaceholder` を配置し、`absolute inset-0` ＋背景画像＋暗オーバーレイ構造で見出し・パンくずを前面表示すること。紺ベタ＋テキストだけの `SubPageHeader` パターンは不可）

### step_7_5.txt に最終検証追加（STANDARD CP）

> `useState` で切り替わる**すべてのビュー（TOP・下層）**のヒーロー先頭に `ImagePlaceholder` が配置されているか確認する。**単色ベタ＋テキストだけのヒーローは不可**。

### ADVANCE CP step_7_4.txt にヒーロー指示を新規追加

元々 ADVANCE の step_7_4 にはヒーローへの言及自体がなかった。STANDARD と同等の指示を追加。

## 効果の予測

| 指標 | 修正前 | 修正後予測 |
|---|---|---|
| 下層ヒーロー画像なしの発生率 | ~100%（指示が曖昧なため確定的） | ~5-10% |

### 高い解決確度の理由

- 原因が「プロンプトの曖昧さ」一点に帰結
- 修正が具体的: 禁止パターンを名指し（`SubPageHeader`）、必須パターンを技術仕様で指定（`ImagePlaceholder` + `absolute inset-0` + オーバーレイ）
- LLM は具体的・明示的な指示に対して従順

### 残存リスク

- 出力コード量が非常に大きい場合、LLM がショートカットとして簡易ヘッダーを使う可能性
- Manus 側で生成する画像の数が増えるため、Manus タスクの実行時間がやや延びる可能性
