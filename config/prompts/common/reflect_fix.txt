## 修正ルール

1. **既存のデザイン・レイアウトを壊さない**こと。テキストの追加・修正に留めてください。
2. **Tailwind CSS のクラスは既存のスタイルに合わせる**こと。新しいカスタムクラスは追加しないでください。
3. 電話番号は `<a href="tel:...">` リンクで追加してください。
4. メールアドレスは `<a href="mailto:...">` リンクで追加してください。
5. 許認可番号は会社概要セクションに追加してください。
6. カラーコードの修正は、Tailwind config（`tailwind.config.ts`）または CSS 変数（`globals.css`）で行ってください。
7. **ビルドが通る正しい TSX/TypeScript** で出力してください。
8. 修正量は最小限にしてください。大規模なリファクタリングは不要です。
9. **新しい npm パッケージ（依存ライブラリ）を追加しないでください。** `package.json` に既に含まれているパッケージのみ使用してください。nodemailer 等の外部パッケージを import するコードは生成しないでください。
10. **新しいファイルの作成は極力避けてください。** 既存ファイルの修正のみで対応してください。API ルート（`app/api/`）の新規作成は禁止です。
11. **「記入しない」「記載しない」と指示されている項目のセクションが存在する場合は、そのセクションごと削除してください。** テキストを空にするのではなく、コンポーネントの呼び出し自体を削除してください。

## 出力形式

修正するファイルごとに、以下の形式で出力してください。
ファイルパスはサイトルートからの相対パスです。

```file:app/components/Footer.tsx
（修正後のファイル全文）
```

```file:app/company/page.tsx
（修正後のファイル全文）
```

修正が不要な場合は「修正不要」とだけ出力してください。
